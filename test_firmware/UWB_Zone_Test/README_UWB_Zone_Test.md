# UWB — тест зон аномалий (3 сценария)

> **Тестовые прошивки, боевые не трогаем.** Проверяют UWB-логику «аномалия = anchor, ПДА = tag» из `MASTER_SPECIFICATION.md` §14.

## Железо

| Что | Кол-во | Роль |
|-----|--------|------|
| ESP32-S3 + BU03 (аномалия) | 2 | **anchor** (role=1), фиксированный UWB ID |
| ESP32-S3 + BU03 (ПДА) | 1–3 | **tag** (role=0), динамический слот 0–10 |
| Питание BU03 | — | На макете — **напрямую 3.3V** (без G42) |

> ⚠️ **Макет без ключа G42:** в обоих скетчах поставьте `#define HAS_BU03_PWR 0` — BU03 питается напрямую 3.3V, ESP не управляет питанием.

## Прошивка

| Устройство | Скетч | Правки |
|------------|-------|--------|
| Аномалия 1 | `UWB_Anomaly_Test/UWB_Anomaly_Test.ino` | `ANOMALY_ID 1`, `UWB_ANCHOR_ID 1` |
| Аномалия 2 | тот же | `ANOMALY_ID 2`, `UWB_ANCHOR_ID 2` |
| ПДА 1 (собранный, с экраном) | `UWB_PDA_Test_Display/UWB_PDA_Test_Display.ino` | `PDA_ID 1` |
| ПДА 2 (если есть) | `UWB_PDA_Test/UWB_PDA_Test.ino` | `PDA_ID 2` |
| ПДА 3 (если есть) | тот же | `PDA_ID 3` |

Board: **ESP32 Dev Module** (S3), Upload Speed 921600, Monitor **115200**.

> **Важно:** у каждой аномалии **свой** `UWB_ANCHOR_ID` (1 и 2). У всех ПДА — **одинаковый** канал/скорость (`BU03_CH 1`, `BU03_RATE 1`), как и у аномалий. Один канал на весь полигон.

## Собранный ПДА с экраном — третий вывод информации

Serial Monitor одновременно тянет только **2 COM-порта**. Собранный ПДА с экраном решает это: он работает на `UWB_PDA_Test_Display` и показывает статус **прямо на TFT** — третий «Serial» без COM-порта.

| Что на экране | Смысл |
|---------------|-------|
| `СЛОТ: 0` | Выданный аномалией слот (зелёный = BU03 принял) |
| `BU03: OK` | Связь с BU03 по UART |
| `УРОН: +10 x5` | Последний урон и общий счётчик |
| `RAD: +0 x0` | Последняя радиация и счётчик |
| `DMG MAC: …` | MAC аномалии, которая бьёт (видно «две аномалии» в сценарии 1/3) |
| `SLOT MAC: …` | MAC аномалии, выдавшей слот |

**Итог по выводам:** 2 Serial (аномалии 1 и 2) + экран собранного ПДА = 3 потока информации одновременно. Если ПДА 2/3 — без экрана, их логи смотрят по очереди (или подключают по одному).

## Как это работает

```
ПДА ──ZONE_HELLO──▶ Аномалия (ESP-NOW broadcast)
Аномалия ──ZONE_ASSIGN slot=N──▶ ПДА
ПДА ──AT+SETCFG=N,0,1,1──▶ BU03 (tag, слот N) ──SLOT_READY──▶ Аномалия
Аномалия ──AT+DISTANCE──▶ BU03 (anchor)  ← меряет САМА, каждые ~1 с
Аномалия: dist ≤ radius → DAMAGE/RADIATION по MAC из таблицы слотов (unicast)
ПДА ──SLOT_RELEASE──▶ Аномалия (выход из зоны / таймаут)
```

- Урон идёт **unicast по MAC** из таблицы слотов — не broadcast. Это и есть проверка «кому аномалия отправит урон».
- Слот освобождается по `SLOT_RELEASE` или таймауту `ZONE_TIMEOUT_MS` (5 с без пакетов от ПДА).
- В тесте ПДА шлёт `ZONE_HELLO` каждую секунду — аномалия видит «ПДА рядом» по ESP-NOW, а **в зоне или нет — решает UWB** (`AT+DISTANCE`).

## Сценарий 1 — один ПДА в радиусе двух разных аномалий

**Сетап:** 2 аномалии (ID 1 и 2) + 1 ПДА. ПДА стоит так, чтобы попадать в радиус обеих.

**Ожидаем в Serial ПДА:**
```
ZONE_ASSIGN slot 0 from <MAC аномалии 1>
ZONE_ASSIGN slot 0 from <MAC аномалии 2>
DMG +10 mask=0x1 (total 1) from <MAC аномалии 1>
DMG +10 mask=0x1 (total 2) from <MAC аномалии 2>
```

**Ожидаем в Serial аномалии 1:**
```
ZONE_HELLO from <MAC ПДА> → slot 0
SLOT_READY slot 0
DIST: 1.20 m
DMG slot 0: 1.20 m ≤ 3.0 m
```

**Проверка:** ПДА получает урон **от обеих** аномалий; каждая аномалия бьёт **только своего** слота (у каждой свой слот 0 — слоты локальны для аномалии).

## Сценарий 2 — несколько ПДА в радиусе одной аномалии

**Сетап:** 1 аномалия + 2–3 ПДА (второй/третий — перепрошитые uwb+esp без экрана). Все ПДА в радиусе.

**Ожидаем в Serial аномалии:**
```
ZONE_HELLO from <MAC ПДА 1> → slot 0
ZONE_HELLO from <MAC ПДА 2> → slot 1
ZONE_HELLO from <MAC ПДА 3> → slot 2
SLOT_READY slot 0
SLOT_READY slot 1
SLOT_READY slot 2
DMG slot 0: 1.10 m ≤ 3.0 m
DMG slot 1: 1.30 m ≤ 3.0 m
DMG slot 2: 1.50 m ≤ 3.0 m
```

**Проверка:** у каждого ПДА **свой слот** (0, 1, 2), урон уходит **всем** в радиусе, каждому — по его MAC. Если один ПДА ушёл из радиуса — `DMG slot N: 4.20 m > 3.0 m` (вне зоны), остальные продолжают получать.

## Сценарий 3 — несколько ПДА в радиусе нескольких аномалий

**Сетап:** 2 аномалии + 2–3 ПДА. Комбинированный стресс-тест: все ПДА в зонах обеих аномалий.

**Ожидаем:** каждый ПДА получает `ZONE_ASSIGN` от **обеих** аномалий и урон от обеих; каждая аномалия держит свою таблицу слотов (0, 1, 2…).

**Проверка:** суммарный урон ПДА = урон аномалии 1 + урон аномалии 2. В логе ПДА видны `DMG` от двух разных MAC.

## Диагностика

| Симптом | Причина |
|---------|---------|
| `[BU03] NO LINK` | Проверить G1/G2 (TX/RX не перепутаны), питание BU03 (3.3V напрямую на макете) |
| `DIST: no data` | Нет второго BU03 в эфире / ПДА не получил слот / канал-скорость не совпадают |
| `ZONE_HELLO` есть, `SLOT_READY` нет | ПДА не смог `AT+SETCFG` — смотреть `[BU03] SETCFG slot N FAIL` |
| Урон не идёт, хотя ПДА рядом | `AT+DISTANCE` возвращает `> radius` — проверить `CFG_RADIUS_M`, калибровку `AT+SETDEV` |
| ПДА получает урон от «чужой» аномалии | У аномалий одинаковый `UWB_ANCHOR_ID` — задать разные (1 и 2) |
